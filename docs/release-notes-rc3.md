# LibrePods 1.0.10-RC3

## 界面

- 底部导航顺序为 **设备、设置、统计**。设备页沿用原主页，原右上角的应用设置入口移到第二项。
- 保留现有 Apple / Material 两套主题及深浅色。各标签保留自己的页面返回栈；在设置、统计根页按返回键会先回到设备页。
- 统计页支持日 / 周 / 月切换和历史时段翻页，展示累计佩戴时长、次数、平均每次时间、最长一次时间。
- 日视图展示每小时分布和单次佩戴记录；周、月视图展示每日分布和每日明细，可点击日期进入当天。
- 进行中的佩戴计入统计，页面可见时每 10 秒刷新一次。没有历史时展示空状态，不填充示例数据。

## 记录与统计口径

- 读取已有的 AirPods 入耳检测事件，不以播放音乐或蓝牙连接时长替代佩戴时间，也不依赖自动播放 / 暂停开关。
- 任意一只入耳开始一次佩戴；一只换成两只或摘下一只仍属于同一次；两只都摘下、两只回盒充电、控制连接断开或服务正常结束时停止。
- 仅 BLE 模式使用现有扫描器通过已保存 IRK 验证的耳机广播；控制连接在线时以控制通道为准。BLE 过期后结束到最后收到信号的时间。
- 时长依据单调时钟计算，避免调整系统时间导致单次时长突然增加或变为负数。历史区间存储为绝对时间，按查看时的本地时区分组。
- 日期按本地午夜划分，每周从周一开始。跨午夜会分摊时长到两天，并在两天各显示该次佩戴；周、月汇总对同一次佩戴只计一次，不能把每天的次数直接相加作为周次数。
- 平均值 = 该时段累计时长 / 该时段内有佩戴时长的会话数；最长一次只取该时段内的部分。进行中的会话也按已发生时长计入。
- SQLite 数据只保存在应用私有目录，无额外联网或权限。统计从使用本版本开始，不能恢复安装前的历史。
- 后台服务每 15 秒保存进行中记录；进程意外终止后，下次初始化只恢复到最后保存点，不把无法观测的离线时间累计进去。系统杀后台、关闭蓝牙或耳机检测信号缺失仍可能造成少量误差。

## 构建与安装

版本代码为 **86**。沿用现有构建环境：JDK 21、Android SDK 37.0、NDK 30.0.14904198、CMake 3.22.1。

```bash
cd android
./gradlew testFossDebugUnitTest assembleFossDebug
```

正式覆盖更新请使用此前 RC1 / RC2 的同一套签名构建：

```bash
./gradlew assembleFossRelease
```

项目已有的 `local.properties` 中四项 `RELEASE_*` 或 GitHub Actions 中的同名签名配置可继续使用。没有这些配置时，Debug 包使用本机构建的调试签名，**不能直接覆盖不同签名的旧版**。不要为安装测试包直接卸载旧版，否则原设置和本地数据会被清除。

GitHub Actions 默认仅测试、构建；发布仍需手动触发工作流并开启 `publish_release`。

## 真机验收

自动测试覆盖统计计算与佩戴会话边界；它们不能替代 AirPods / HyperOS 真机验证。建议在沿用原签名的测试构建上检查：

1. 三个标签切换、二级页面返回，以及两种主题和大字体下的底部遮挡。
2. 单耳入耳 → 双耳入耳 → 摘下一只 → 两只都摘下，应计一次；重新入耳应计第二次。
3. 关闭自动播放 / 暂停后，佩戴统计仍继续记录。
4. 蓝牙断开、两只回盒、服务终止后计时停止；重开应用读取已保存记录。
5. 只关掉界面、保持后台服务时继续记录；系统杀进程后不补算离线间隔。
6. 跨午夜的时长分到两天，周 / 月汇总仍只计一次；仅 BLE 模式离开广播范围后结束计时。

保留 RC2 的开盖优先连接手机、系统蓝牙电量同步、语音助手后台 / 锁屏权限引导等已有功能。
